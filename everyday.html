Is it approved?

A shop owner wants to review a notice before an automation releases it. VetoLatch makes that decision state explicit. This example releases only a terminal preview; it never sends or posts anything.

Example shop notice: our window display will change for one afternoon.

Pending

The draft exists. Dispatch is not authorized. The exact text is visible for review.

Your decision

Type approve or reject in the local example. Any other input blocks release.

Recorded result

Approval renders a terminal preview. Rejection releases no preview. Decision and outcome share stable action/review identities.

Try it in your own environment.

Python 3.10+. Save shop_notice_review.py into a new folder, then run:

python -m venv .venv
# Windows
.venv\Scripts\python -m pip install vetolatch==0.4.0a1
.venv\Scripts\python shop_notice_review.py
# macOS / Linux: use .venv/bin/python instead

What was actually checked?

A maintainer installed public vetolatch 0.4.0a1 into a fresh environment outside the source checkout and ran scripted approve, reject and invalid-input cases. All three branches behaved as described. This is engineering verification, not an independently executed human evaluation.

The SDK is an in-memory reference state machine for a trusted local process. Actor labels do not authenticate people; audit events are not tamper-proof. A production integration must authenticate the decision owner, protect state and bind permission to the exact action.

Where UniversalMind fits

VetoLatch is the public governance boundary extracted from private UniversalMind research. The private workbench can surface a proposal and wait for a decision. In a fresh three-input check, both everyday prompts and an unrelated control received the same recommendation. Its current demonstration therefore establishes the review workflow—not business expertise, general intelligence or a better real-world decision.
